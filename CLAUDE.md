# Solar Lights Lite

Controller: ATmega328P Pro Mini-class board (reference BTE13-010A clone), fuses
L 0xE2 / H 0xD9 / E 0xFD = internal 8 MHz, BOD 2.7 V, no bootloader. PlatformIO
project `firmware/controller`, board `pro8MHzatmega328`, environments
`standalone` / `production` / `advanced` (TELEMETRY 0/1/2). Telemetry: Wemos D1
Mini with ESPHome (`firmware/esphome`), Home Assistant files in `homeassistant/`.
Docs in `docs/` are the source of truth (numbered 01–12).

## Never / always

- Flash only over ISP with a standalone avrdude 7.x; never `pio run -t upload`
  (PlatformIO's bundled avrdude fails verification with this setup).
- Do not port to the ATmega32U4: firmware relies on 328P PCINT2, ADC mux 0x0E
  bandgap and Timer1 register layout.
- All tuneables live in `firmware/controller/include/config.h`; `schedule.h`
  must stay free of Arduino/AVR headers (host tests compile it).
- The telemetry line is a protocol: space-separated `key=value`, starting with
  `fw=`. `main.cpp` `printLine()` and BOTH ESPHome lambdas must change together.
- Both ESPHome profiles keep device name `solar-lights`, identical entity names
  and the same encryption key, so HA history carries across tiers.
- LED string is low-power, driven directly by D9 PWM through R3 47 ohm; no driver
  transistor. Duty is brightness only; R3 + pin resistance (~30 ohm) set current.
- Doc wording: modules A–F, tiers 0/1/2, gates 0–8. No personal machine or
  dated "journey" narrative in docs; history lives in CHANGELOG and tag
  `v0.5.5-history`.

## Hardware gotchas

- Pins: D9 LED PWM, D7 LDR supply, A1 LDR sense (R4 47k to OUT-), D2 button,
  D1/TX -> R8 47k -> Q2 2N3904 -> D1 Mini D6 (inverted, 9600 baud, receive-only).
  D8, D10, D11, A0 unused.
- Q2 conducts while TX idles high (advanced build, ~0.4 mA); production build
  parks TX low between lines. The link idles in a break state, so the ESPHome
  lambdas trim non-printable bytes from both ends of each line.
- D1 Mini power: Tier 1 = its own micro-USB with U3 OUT disconnected; Tier 2 =
  U3 (TPS63802, 3.3 V) OUT to the 3V3 pin. Never both. D1 G to OUT-, never B-.
- Watchdog clock runs ~12% slow on the reference board: 300 s confirmation is
  ~5.5 real minutes; do not rely on `time=` for wall-clock durations.
- Solar input: Option A (panel Voc <= 6.5 V) direct to M1; Option B via U0 5 V
  buck. The reference 7.6 V Voc panel is Option B.
- TP4056 module has no cell-temperature inhibit (documented known limitation).

## Conventions

- Human-readable dates `dd-mmm-yyyy`; CHANGELOG headings `## [x.y.z] DD-MM-YYYY`.
- Drawings, pin map, bench/USBasp sheets and netlist are generated by `tools/`
  (reportlab + pypdfium2); KiCad PDF/preview via kicad-cli. `docs/ASSEMBLY.html`
  is built from docs 01–12 by `tools/make_guide.py` (markdown): rerun it after
  any doc, drawing or CSV change. Regenerate, don't hand-edit outputs.
- Never commit secrets, `.env`, `.pio/`, `.esphome/` or build output.
